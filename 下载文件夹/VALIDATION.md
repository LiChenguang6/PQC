## 当前版本验证范围

- ARM64/x86_64 的 8 次 Unicorn 指令执行，验证页面标题与播放 URL 的 ASCII/中文/表情复制、原寄存器及返回路径恢复。新增叶子代码没有调用、分配或 GC safepoint，不保留 Dart 堆对象引用。
- 两种架构共 12 条主页标签路径：`index`、缺省和 `video` 指向“视频”，其他显式标签仍保留原索引。
- 原 `_doLoading` 从入口到最终完成调用之前的指令字节全部保留，网络检查、Await 选线、登录、广告数据获取与网络初始化未跳过。完成调用改为原广告跳过动作，只取消计数器读取和非零阻拦。其后原存储值/初始化数据的判断保持原字节；6 条机器执行分别验证就绪可进主页、空值或空配置走原初始化失败提示。
- AOSP API 29 x86_64 中运行生产 PlayerCapture JNI 和原 libmpv，合成视频真实播放。测试专用辅助库写入有界页面快照，验证页面标题优先于 MPV 文件名、不同 URL 不串标题、写入中的快照不采用。实际 Dart 字符串复制由上面的机器执行独立验证；不把辅助写入当作真实平台页面验证。
- 文件名测试验证中文/表情、非法字符替换、扩展名、空标题回退及 UTF-8 长度限制。生产前台下载服务实际下载两个同标题任务，返回桌面后两份 MP4 均完成、分别命名且经 FFmpeg 完整解码，未覆盖已有文件。
- 最终 APK 覆盖安装；原 Flutter Activity 加载修改后的 libapp 与原 libflutter，进程存活，日志未发现 native fatal 或 snapshot 不兼容。软件模拟器启动等待可能超时，库映射和进程存活单独检查。

## 线路调查与限制

原 AOT 证据：`chooseAPILines` 并发请求 `/api/sys/live`，使用最先满足 200–299 的响应；Duration 为 15,000,000 微秒。启动完成后才创建广告组件，计数初值 5，周期 1 秒。这说明广告等待与真实网络选线是分开的。

云端代表性候选地址没有连通，备用 CloudFront 配置返回 403。结果是失败探测耗时，不是成功选线耗时，也不是用户手机实际启动时间。未修改 TLS、请求认证或播放授权，没有强行把网络失败判作成功。真实平台启动自动跳转和详情标题仍缺少端到端实测。

## 原生文件审计与回归边界

原 21 个原生库中 19 个字节完全一致，原 libmpv/libflutter 不变。只修改锁定的 ARM64/x86_64 libapp，文件长度不变，范围限定为既有滚动/UI 补丁、新启动调用/计数器/默认标签及无调用标题复制片段和所需 ELF 段大小。新增 RW 空间为进程匿名内存，不把标题或 URL 写入原生库文件。

ARMv7 不含这些 AOT 修改。Java 命名逻辑适用于三个 ABI。标题捕获只覆盖原详情播放页的 getter；其他入口与未获得匹配快照的情况仍回退到播放器标题。旧队列记录没有重新推断或重命名。

`validation/export5-tests` 为本次脚本/结果；export4/export3 和更早结果仅用于历史回归证据，不能当作本次重新完成的所有测试。此前按钮拖动、并发输入 1–32、目录持久化、任务管理保留；本次未再次压测 32 并发，也未实现推荐接口分页。
